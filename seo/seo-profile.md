## 0.1 Stack and deployment

| Item | Finding |
| --- | --- |
| Framework | **React 19 + Vite 7, client-side SPA** with `react-router-dom` v6 (`src/App.tsx`). Not Next.js, not SSR. The `package.json` `name` field says `tanstack_start_ts` but that is a leftover template name — there is no TanStack Start code. |
| Prerendering | **Yes, partially.** `vite.config.ts` uses `@prerenderer/rollup-plugin` with a hardcoded list of **12 routes**: `/`, `/onboardings`, `/ai-support`, `/branding-tool`, `/login-tracking`, `/webinar`, `/affiliate`, `/go`, `/go-paid`, `/breakdown`, `/breakdown-paid`, `/pricing`. Production-only. |
| Built HTML | Prerendered routes contain real content. **Everything else does not.** |
| **Critical defect** | Non-prerendered public routes are served the **homepage's prerendered HTML** by the SPA fallback. Verified live: `/blog`, `/for/med-spas`, `/alternatives/ghlengine` each return a byte-for-byte identical 115,999-byte document — the homepage. To Google and to every AI crawler, those pages *are* the homepage: duplicate content, wrong `<h1>`, wrong title, wrong canonical. |
| Live domain | **https://saassuite.ai** — non-www is canonical (used in `index.html` canonical/OG, `robots.txt` `Sitemap:`, `public/sitemap.xml`, `SITE` in `PageSEO.tsx`, `SITE_URL` in `src/lib/blog.ts`, `AGENCY_BOOKING_URL`). `https://www.saassuite.ai/` **also returns HTTP 200 rather than redirecting to non-www** — a duplicate-host problem to fix in Phase 1. Lovable also serves `saas-suite.lovable.app` and the preview domain; those should not be indexed. |
| Metadata approach | Three overlapping systems: static tags in `index.html`, `PageSEO.tsx` (react-helmet-async, correct approach), and `SEO.tsx` (manual `useEffect` DOM mutation, invisible to non-JS crawlers). Coverage is inconsistent — some pages use one, some the other, many use none. |
| Stray file | `public/index.html` is a second, conflicting HTML document with different titles and a `noscript` block. Vite does not serve it as the app shell, but it is publicly fetchable at `/index.html` and contradicts the real head. |

## 0.4 Site profile

**What the business does.** SaaSSuite is a white-label software layer that HighLevel (GoHighLevel) agencies install on top of their HighLevel account when they resell it in SaaS mode. It supplies the parts HighLevel doesn't: branded interactive onboarding and video training for the agency's end clients, native AI support chat trained on the agency's knowledge base with human handover and ticketing, CSS-level white-label branding (colors, fonts, logo, login page, custom domain), login/behaviour tracking for retention, email warmup, and a separate white-glove "Agency Support" service where the SaaSSuite team does A2P registration, website and automation building, and 24/7 client chat under the agency's brand.

**Brand name variants in use:** SaaSSuite (canonical), SaasSuite, SAASsuite, saassuite.ai. **Recommendation: standardise on "SaaSSuite" everywhere** — inconsistent casing weakens entity recognition. `[INFERRED]`

**Audience:** HighLevel agency owners running or launching SaaS mode — reselling HighLevel as their own branded software. In the site's own words they want to "attract sticky SaaS customers", stop churn, "reduce support tickets", and get clients activated "without a call".

**Their problems (site's words):** clients don't activate, churn, support burden falls on the agency owner, HighLevel looks like HighLevel instead of their brand, no time to build onboarding.

**Geography:** primarily **United States / global English**, USD pricing, no street address anywhere in the codebase. One explicit signal: "100% US team for live calls". `[INFERRED]` — treat as global-English, US-centred; **no LocalBusiness schema, use Organization**. `[NEEDS CONFIRMATION]` — is there a physical business address and phone you want published? None exists in the code.

**Primary conversion goal:** start free / sign up for the software (homepage CTA "Start for free."), with a secondary **book a call** goal for Agency Support (`https://saassuite.ai/book`) and a webinar registration goal.
