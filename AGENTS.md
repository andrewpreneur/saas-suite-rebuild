# Project decisions

- Switchyard branding uses a validated shared navigation-only generator and sandboxed preview; favicon URLs live in an independent branding part and execute only as JavaScript, so legacy styles and unrelated account settings remain intact.

- Theme Customizer app accents reuse the existing top-menu active/hover gradient and stay CSS-only on heavy routes, so paused decoration scans never disable navigation or primary-button colors.

- Hub sections save visibility and visible default per plan in one write.

- Self-service account deletion uses the shared Settings confirmation, service-only transactional cleanup, and unconditional logout/home completion; never delete an impersonated workspace.
- Build Your SaaS uses an isolated fixed-price one-time service checkout with browser-bound payment verification; no kit entitlements, subscriptions or upsells.

- Initialize PostHog once from the shared entry for both app and funnel; capture anonymous pageviews/page exits only, strip queries and hashes, disable replay/autocapture, and honor live tracking opt-out to avoid collecting forms, chats or auth credentials.

- Subdirectories may have their own AGENTS.md; read it before changing files there.

- Old UI is the default for everyone; the new UI (design system v0.1 plus the one-link-per-job sidebar) is opt-in through `newUi` in `src/lib/uiVersion.ts`, a per-browser choice read once at load, and only platform admins see `UiVersionSwitch`. Each restyled shared component is a chooser file in `src/components/ui` that picks `ui/ds/*` (new) or `ui/legacy/*` (old, kept identical to the original). New-only colors, radius and brand-purple mapping are scoped to `html.ds-ui` in `src/index.css`, so the old UI never changes. Any new-UI-only layout must be behind `newUi`.
- Design system v0.1 pieces: color tokens in `src/index.css` (`--brand`, `--warning`, `--info`, `--ink`, `--canvas`), type/shadow scales in `tailwind.config.ts`, components in `src/components/ui/ds`. Control heights use `.ds-control`/`.ds-icon` in the components layer, never `sm:h-*`, so a one-off height on a single button still wins. The new-UI shell sets `body.ds-app` (Inter, self-hosted in `public/fonts`) and paints `bg-canvas`; marketing, funnel and hub pages are not migrated. `/admin/design-system` (platform admins) renders the live components and tokens.
- New-UI sidebar groups live in `NEW_UI_SIDEBAR_SECTIONS` (`src/lib/sidebarNav.ts`): every old link stays, Affiliate, One Feature Kit and Settings get their own links, and sidebar names match page titles.
- Sidebar "More Tools" lists finished tools that were search-only; plan locks and access flags stay in AppSidebar's filter, so adding a link never widens access.
- Design Save never reports success for an edit it did not write: colors with no sidebar style go to `primary_color`/`secondary_color`, font/icon/animation edits stay unsaved until a style is chosen, and a blocked or failed Save says why. Presets keep one rolling "Previous setup" backup, replace by name, and can be deleted (`src/lib/brandingPresets.ts`).
- The docked Copilot width is user-resizable (`src/lib/copilotDock.ts`) and published as `--copilot-dock-offset`; the app column and fixed bars read that variable so nothing sits under the panel.

- Keep MenuAutomationPanel inline, fully expanded; share manual-to-automation tour steps to avoid duplicate flows.
- Show token fingerprints only via authorized status and shared server crypto, never full tokens, to protect credentials.
- Dashboard user dialogs query the selected customer's agency via Supabase and support permissions; never use platform-admin user-360 for agency clients.
- Dashboard video totals derive from the shared standard catalogue plus an exact count of agency-owned custom lessons across its plan IDs, so added lessons never depend on a fixed denominator.
- Public and in-app challenge finales share Chicago-time presentation boundaries and rank-based winner selection; payout copy does not initiate Stripe transfers or change the existing scoring cutoff.
- Challenge deductions exclude audited completion IDs through private review records, never delete education progress; evidence is owner-only and appears only on the signed-in challenge page to prevent public or cross-account disclosure.
- Keep Agency Support purchase, assignment, and projects in separate owner tabs; preserve data flows.
- Keep theme writes scoped to onboarding links an authenticated owner or accepted admin can access, while public theme reads remain available for hub URLs.
- Make the configurable top-nav help widget available to every agency, and hide it whenever HighLevel's visible header is replaced by an embed. Card title, subtitle, show-on (sub-accounts, agency view, or both), and the three options (label, subtitle, icon, target, visibility, order, and new-tab vs embed) are stored per agency on `saas_suite_users.top_nav_widget_options`. Null keeps Help Library, Live Support, and Open a Ticket, with the card subtitle "We're here to help". The button mounts only after the real header controls exist. Embed opens the existing bottom-right popup via `window.SaaSSuitePopup.open`, then `postMessage` `{ type: "saassuite:popup-open", source: "saassuite-host", tab, tabName, path }` and `/popup/<agency>?tab=` using education, support-chat, support-ticket, or docs. The popup iframe is 400 by 640, capped to the viewport, and follows `{ type: "lvb-popup-preferred-size", width, height }` from the loader.
- Match HighLevel menu links by both metadata and URL while preserving the sidebar's vertical layout, because its markup varies across account views and releases.
- Team-admin permissions live on `account_admins` (per-area none/view/edit plus assigned-only flags) and are enforced both in RLS helpers (`support_can_*`) and the UI via `useTeamAccess`, so hiding a button is never the only protection.
- Ticket/chat assignee notifications come from database triggers that call `notify-support-assignee`, so every write path (UI, rules, edge functions) notifies consistently.
- Onboarding auto-pay cards are saved only by the `onboarding-autopay` function (a DB trigger blocks client writes), so a client can't point charges at someone else's card.
- Support alert routing (assignee → owner default when human_chat_mode is "self" → SaaS Suite when "managed") lives in `notify-support-assignee` and `get_support_alert_context`, and Slack alert toggles are enforced inside `slack-notify`, so every trigger path routes and filters the same way.
- Admin invites take the on-screen account as owner (verified owner or platform admin) and deliver one generated sign-in link through a GoHighLevel inbound webhook, because impersonated invites were being filed under the inviter's own account.
- All customer email goes through GoHighLevel. The app POSTs a flat JSON event to an inbound webhook and a GoHighLevel workflow sends the email. Never add a direct email provider. New email types need a new webhook URL secret and a GoHighLevel workflow (coordinate with the GHL Dev bot). Server-side Purchase goes through Stape. The standing rule is `.cursor/rules/email-via-ghl.mdc`. Shared sender: `postGhlEmailEvent` in `supabase/functions/_shared/ghl-email-webhook.ts`.
- Chat/ticket insert triggers use support_pick_assignee for owner/person/round-robin/type defaults, preserving reps across creation paths.
- Each WebinarKit campaign has distinct registration/confirmation routes, webinar IDs and CRM destinations; share capture/attribution.
- Agency IDs are owned by the ensure_agency_id trigger: never blank, Plan 1 (agency_id_basic) always equals agency_id, and a name change renames all plan IDs (slug, slug-2, slug-3) when free — so the UI never generates or "creates" IDs.
- Keep the public `/setup` knowledge base account-neutral and driven by structured local content, so search, navigation, and plan documentation never query or expose customer data.
- Public support questions are accepted only through the rate-limited `public-support-submit` function and stored in `public_support_submissions`, so visitors cannot read or alter the queue.
- Keep `/special` focused on the $997 annual offer with its checkout inline; $97 Advanced and $297 Premium Support remain secondary monthly alternatives.
- Use `useGhl` + `LocationList`/`MenuLinkPicker` for populated connected accounts, manual entry otherwise; `connectionAgency` resolves plan IDs. Forced refresh uses `loadGhlSnapshot`: sync before reading both lists, even without menus, to include new accounts.
- Installation menu loads always sync before reading; discard superseded responses and replace old Hub selections only with a unique exact current-agency Hub URL, to keep renamed installations current without guessing between duplicates.
- The interactive walkthrough has two parts — navigation (sidebar) and Client Hub features — and their auto-start/resume/weekly-dismissal rules live only in `src/lib/tourSchedule.ts`, so every entry point follows the same limits.
- Team admins never own an account row: `register_starter_user` and a BEFORE INSERT trigger on `saas_suite_users` skip them, and an `account_admins` trigger deletes their empty Starter — because many signup/login paths recreated it.
- xxidesigns additions go only in its active assets; mobile panels inherit native surfaces and keep native nav, branding, widget color and zoom gates.

- Chat tickets validate access server-side, use stored history, and are idempotent.
- Admin Support refreshes via refreshSupportInbox to keep rows/counts in sync. Live `/admin/support` messages subscribe once the Supabase Auth session exists (`realtime.setAuth`) on one stable channel for `ai_chat_messages`, `agency_owner_messages`, `chat_threads`, `support_tickets`, and `support_ticket_replies`, and poll the open conversation while the tab is visible. Those four SELECT policies are `TO authenticated` and call `(SELECT platform_support_excluded_keys())` inside an InitPlan (empty unless `(SELECT is_platform_admin())`). Do not inline the excluded-agency join, do not leave the policies `TO public`, and do not unwrap those zero-arg calls: anon runs first in Realtime and a per-row keys() call times out. `anon` has EXECUTE on `platform_support_agency_key(text)`. Email matches use `NULLIF((SELECT current_auth_email()), '')`. `support_ticket_replies` are readable only when the parent ticket is. `agency_owner_messages` keeps its public SELECT policy.

- START HERE reuses CoPilotShell inline for identical chat, voice, sounds and shared history; omit floating close/minimize controls. The existing popup primitives are retained to preserve exact functionality without a transport migration.

- Signed-in Copilot is /app/copilot (chat-copilot); public /copilot uses public-copilot + publicCopilotPolicy so visitors never reach account tools.
- Re-Onboard replays slides in a fresh thread with thread-scoped phases, preserving previous chats and account settings.
- copilotStream/workspaceStream provide SSE; popup retains JSON. Topic-filtered transcripts augment, not replace, live tools/context.
- Copilot billing/tool gates share server policy; authenticated upgrade buttons use Stripe directly, preserving subscriptions/team permissions.

- Menu-removal cards own pacing and trusted links; history-aware video offers stay replayable. SnapshotImportActions shares copy/new-tab imports across chat and automation.
- Cross-agency admin support automation uses `admin-support-api` (ADMIN_SUPPORT_API_KEY) reusing portal reply/notify paths.
- Agencies that run their own support are listed in `platform_support_excluded_agencies` by owner email. `is_platform_support_excluded` keeps their chats, handovers, and tickets out of the Grok handover webhook, the Andrew LeadConnector ping, `/admin/support`, and `admin-support-api`. Their own support views, assignee alerts, and ticket creation stay. Platform-admin SELECT on `chat_threads` and `support_tickets` resolves that excluded-id set once per query, so `/admin/support` ticket and AI-conversation lists stay under the authenticated statement timeout. Non-admin reads still use `can_access_agency` and `support_can_see_*`.
- Training opt-ins on `/onefeaturetraining-*` (including the quiz) go through `one-feature-lead`, mapping `has_ghl` to `has_highlevel`. `/onefeaturetraining-5` posts `action: "create"` before Yes/No, so `has_highlevel` may be absent until the later `highlevel` or `plan` update. Quiz create may omit `phone` or send an empty phone. Other training pages still require a phone. `selected_plan` is `97|297|497|none|not_sure`. `/agents`, `/highlevelers`, and `/highlevelers-upgrade` write `funnel_apply_leads` through `funnel-apply`. `/work-with-us` writes only through the JWT `work-with-us-apply` function. Work-with-us stays lead-only: `ss_lead_only` skips `register_starter_user`. Agents, work-with-us, and HighLevelers post to separate inbound webhook secrets. HighLevelers posts on done, and a stuck opt-in is posted when `funnel-apply` runs again after 60 minutes. That stuck post records `stuck_sent_at` only after the webhook succeeds, so a failure is retried, and step `done` still posts while `handoff_sent_at` is empty. `/founders-plan` writes the same `funnel_apply_leads` table through `funnel-apply` with `funnel` `founders_plan` and steps `optin` then `done` (one row per email). Done posts `GHL_FOUNDERS_PLAN_INBOUND_WEBHOOK_URL` when that secret is set. A missing secret still saves the lead. Every 14-day trial CTA uses `FOUNDERS_PLAN_TRIAL_URL` (`https://founder.gohighlevel.com?fp_ref=russel-andrew`). Keep the dual trial and Upgrade Now buttons and the bonuses form. Upgrade Now and the thanks link stay on the in-app affiliate-upgrade URL, not the www saasupgrade link. Do not apply `20261027181500_founders_plan_funnel.sql` from an agent.

- Ospry (Legion, px.lspxl.com) is the site consent banner and bundles trackers; it loads unconditionally first in index.html head, and no in-app cookie banner is rendered so visitors never see two.
